将 `sys_get_time` 中直接用指针访问内存地址改为用虚拟内存管理的方式访问。即用 `translate_byte_buffer` 获取指针所指向区域，再将数据转化为字节写入。

将 `sys_trace` 中直接用指针访问内存地址改为用虚拟内存管理的方式访问。遍历 `memset` 中的 map areas 来检查所要访问的地址是否对用户可见，然后再通过 page_table 获取 virt addr 对应的 page table entry，检查是否可读和可写。最终通过 pte 查询到物理地址，进行读写操作。

完成 `sys_mmap`。计算出需要映射的地址范围 `start_va` `end_va`，检查是否符合要求，然后调用 memset 的 `insert_framed_area` 创建新的地址映射。

完成 `sys_munmap`。与 `map` 相同，只不过调用 `memset.shrink_to` 来销毁一段分配的地址。

## 完成问答题

1. PTE 包含预留的10位、44位物理页号以及标志位。标志位中 V 表示页表项是否合法、R/W/X 表示对应页面是否允许读/写/取指、U 表示 CPU 处于 U 特权级时是否允许访问、A 记录自从页表项上的这一位被清零之后页表项的对应虚拟页面是否被访问过、D 记录自从页表项上的这一位被清零之后页表项的对应虚拟页表是否被修改过。

2. mcause 寄存器中会保存发生中断异常的原因，其中 Exception Code 为 12 时发生指令缺页异常，为 15 时发生 store/AMO 缺页异常，为 13 时发生 load 缺页异常。

CSR寄存器:

- scause: 中断/异常发生时， CSR 寄存器 scause 中会记录其信息， Interrupt 位记录是中断还是异常， Exception Code 记录中断/异常的种类。
- sstatus: 记录处理器当前状态，其中 SPP 段记录当前特权等级。
- stvec: 记录处理 trap 的入口地址，现有两种模式 Direct 和 Vectored 。
- sscratch: 其中的值是指向hart相关的S态上下文的指针，比如内核栈的指针。
- sepc: trap 发生时会将当前指令的下一条指令地址写入其中，用于 trap 处理完成后返回。
- stval: trap 发生进入S态时会将异常信息写入，用于帮助处理 trap ，其中会保存导致缺页异常的虚拟地址。

Lazy 策略虽然牺牲了第一次加载所需的时间，但其节省了宝贵的内存空间资源。

10 GB 除以每页 4096 B 再乘每 PTE 8 B 得到总占用 20 MiB 左右。

收到内存分配申请后不进行映射创建，而只是做记录。之后在遇到对应的 page fault 并进行错误处理时再进行分配。

swap 后的 PTE 将 V 置 0 表示失效。

3. 将内核页面的 pte 的 `U` 标志位设置为0。

在内核和用户态之间转换时不需要更换页表，也就不需要跳板，可以像之前一样直接切换上下文。

双页表实现下用户程序和内核转换时、用户程序转换时都需要更换页表，而对于单页表操作系统，不同用户线程切换时需要更换页表。
